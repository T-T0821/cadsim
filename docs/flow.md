# 工程シミュレーションの設計

「工程シミュレーション」ウィンドウ(ツールレールの「工程」)のしくみをまとめます。使い方は [README](../README.md#工程シミュレーションでスループットを見る) を見てください。

## 層の分け方

ドメインは `crates/cadsim_core/src/flow/`、保存形式・Excel・画面はアプリの `src/flow/` にあります。`record` と `xlsx` は Bevy に依存しないアダプターで、`cadsim_io` ができたらそちらに移します([architecture.md](architecture.md))。

| ファイル | 層 | 内容 |
| --- | --- | --- |
| `cadsim_core` の `flow/model.rs` | ドメイン | 工程モデル(`FlowModel` / `Element` / `ElementKind`)、追加・削除・並べ替え、回せない理由の検証、サンプルライン |
| `cadsim_core` の `flow/sim.rs` | ドメイン | 離散事象シミュレーション(`Simulation`)と集計(`Report`) |
| `cadsim_core` の `flow/palette.rs` | ドメイン | 状態・稼働率の色(3D ビュー・グラフ・Excel で共通) |
| `cadsim_core` の `flow/scenario.rs` | ドメイン | 案(名前つきの設定の写し)と、種を変えた繰り返し実行・集計(`compare_scenarios`) |
| `record.rs` | アダプター | `.cadsim` に書く形(serde)。部品は木の中の位置で指す |
| `xlsx.rs` | アダプター | 結果の Excel 書き出し(`rust_xlsxwriter`) |
| `mod.rs` | UI | `FlowRes`(モデルの包み)、`FlowRun`(実行中のシミュレーションと再生)、`FlowColors`(3D の部品に塗る色)、保存ダイアログ |
| `ui.rs` | UI | ウィンドウ(工程・人員・案の比較・結果・グラフのタブ) |
| `staff_ui.rs` | UI | 人員タブ([staffing.md](staffing.md)) |
| `scenario_ui.rs` | UI | 案の比較タブ |

3D の部品とは `Element::part`(ノード ID)だけでつながります。`view/viewport.rs` の `sync_views` は、`FlowColors::color_on_path`(自分か一番近い祖先の色)があれば部品の色の代わりに使います。選択・干渉の強調はそれより優先します。

## モデル

| 要素 | 受け取り | 送り出し |
| --- | --- | --- |
| 生成 | — | 間隔(± ばらつき、一様分布)ごとに1個作る。送れなければ持ったまま詰まり、送れた時点から次の間隔を数える。上限個数を付けられる |
| 工程 | 空いていれば1個 | サイクルタイム(± ばらつき)の加工が終わったら送る。送れなければ詰まり |
| バッファ | 容量まで | 先入れ先出しで、送れるだけすぐ送る(滞留時間 0) |
| 排出 | いくらでも | — |

工程に「人が要る」を付けると、作業者が来るまで「人待ち」で止まります。作業者の割り当て・シフト・人数の比較は [staffing.md](staffing.md) にあります。

送り先が複数あるときは並び順に見て、最初に受け取れる先へ送ります(並列の設備や分岐に使えます)。合流で複数の上流が同時に空きを待っているときは、一覧で上にある要素が先です。

### 故障

工程に MTBF・MTTR を入れると、**加工している時間**で数えた故障までの時間を平均 MTBF の指数分布で引きます。加工の途中で故障したら、平均 MTTR の指数分布の時間だけ止まり、直ったら残りの加工を続けます。修理が終わるたびに次の故障までの時間を引き直します。

### 乱数

自前の SplitMix64 を使い、種(`RunSettings::seed`)から決まります。同じモデル・同じ種なら必ず同じ結果になるので、設定を変えたときの差だけを比べられます。

## シミュレーションの進め方

事象(生成・加工終了・故障・修理終了)を時刻順の優先度付きキューに入れ、1つ処理するたびに `settle` で「送り出せるワークを、動かなくなるまで下流へ動かす」を繰り返します。下流が空くと、詰まっていた上流が同じ時刻に連鎖して動きます。工程ごとに予定される事象は常に1つなので、取り消しは要りません。

`Simulation::advance(until, max_events)` で途中まで進められます。画面の ▶ は毎フレーム「経過時間 × 速度」だけ進め、1フレームの事象は 20 万件までにして画面が固まらないようにしています。⏩ 最後までは同じ関数を上限なしで呼びます。途中まで進めた結果と一気に回した結果は一致します(テスト `stepping_matches_a_full_run`)。

0 秒の工程が輪になると時間が進まなくなるので、時間は 0.01 秒以上に制限しています。

## 集計

立ち上がり時間より前は数えません(状態の時間・通過数・仕掛数の積分を、立ち上がり時刻で切ります)。

| 値 | 求め方 |
| --- | --- |
| 状態の割合 | 工程・生成の状態(稼働・待ち・詰まり・故障)ごとの時間 ÷ 集計時間。生成は待ち(間隔待ち)と詰まりだけ |
| 排出数・スループット | 集計期間に排出に届いた数、それを 1 時間あたりにした値 |
| サイクルタイム | 集計時間 ÷ 排出数 |
| リードタイム | 生成されてから排出に届くまでの平均 |
| 仕掛数 | 生成から送り出されて排出に届くまでのワーク数の時間平均と最大(生成が持ったままのワークは数えない) |
| 平均加工時間 | 工程の稼働時間 ÷ 通過数 |
| 平均の中身 | 工程・バッファの中のワーク数の時間平均 |
| ボトルネック | 稼働 + 故障の割合が一番高い工程 |
| 電力量 | 定格電力 × 稼働時間 + 待機電力 × それ以外の時間(待ち・詰まり・故障)。バッファはワークがある間を稼働とみなす |
| エア消費量 | エア消費量(L/min)× 稼働時間 |

グラフ用に、回す時間を 240 等分した時刻ごとに、仕掛数・排出数の累計・各要素の状態を記録します。

## 3D の色分け

- **状態**: 実行中のシミュレーションの今の状態の色(稼働 緑・待ち 黄・詰まり 橙・故障 赤)。
- **稼働率・ボトルネック**: 稼働 + 故障の割合を青 → 緑 → 黄 → 橙で塗り、ボトルネックは濃い赤。

工程の設定を変えると結果が古くなるので、色分けを消し、ウィンドウに回し直すよう表示します。

## 案の比較

`FlowModel::scenarios` に `Scenario { name, model }` を並べます。`model` は工程・回す条件・名簿をまるごと写したもので、案の中には案を持ちません(`FlowModel::without_scenarios`)。`save_scenario` で今の設定を写して足し、`load_scenario` で案の設定を今の設定に戻します(案の一覧はそのまま残ります)。

案は設定の一部ではないので、「結果が古いか」は案を除いて比べます(`FlowModel::same_setup`)。案を足したり名前を変えたりしても、▶ の結果や人数の比較は古くなりません。

`compare_scenarios(cases, replications)` は、案ごとに種を `seed`, `seed + 1`, … とずらして `replications` 回(1〜100)回し、排出数・スループット・作業者の稼働率・人待ち・仕掛数・リードタイム・1 個あたりの電力量の平均・最小・最大(`Summary`)を出します。ボトルネックはいちばん多くの回でボトルネックだった工程です。どの案も同じ種の並びで回すので、案どうしの差は設定の差だけから来ます(共通乱数)。回せない案があれば、理由に案の名前を付けて返します。画面は「今の設定」と全部の案を渡し、排出数の平均がいちばん多い行(`ScenarioComparison::best`)を緑にします。

## Excel 書き出し

`rust_xlsxwriter` で3枚(作業者がいれば4枚)のシートを書きます。

- **概要**: ラインの集計と、回した条件・要素ごとの設定
- **設備別**: 要素ごとの状態の割合・通過数・故障回数・平均加工時間・中身・電力量・エア消費量と、状態の割合の積み上げ横棒グラフ(Excel のグラフとして入れるので、Excel で色や体裁を変えられます)
- **推移**: 時刻ごとの排出数の累計と仕掛数、その折れ線グラフ
- **作業者別**: 作業者ごとの稼働率・作業・歩行・手待ちの割合、出勤時間、作業数、歩いた回数
