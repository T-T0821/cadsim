# 部品スクリプトの設計

部品(ツリーのノード)に [Rhai](https://rhai.rs/) のスクリプトを付け、PLC 連携の「部品スクリプト」モードで PLC の代わりに設備を動かす。

## 層の分け方

| 層 | ファイル | 内容 |
| --- | --- | --- |
| ドメイン | `model.rs` の `Node::script` | スクリプトのソース。ノードに持つので、保存(`NodeRecord::script`)・元に戻す(ノードの写し)・形状の差し替え(ID が残る)はほかの設定と同じに扱われる |
| ユースケース | `scripting/runner.rs` | `ScriptRunner`: 1つのスクリプトをシミュレーションの時刻に合わせて動かす。シミュレーター側はポート `ScriptHost` を実装する |
| ユースケース | `scripting/controller.rs` | `ScriptController`: 部品ごとの `ScriptRunner` を、PLC 連携の I/O・センサー・内部信号につなぐ (`ScriptHost` の実装 `IoHost`) |
| アダプター | `scripting/rhai_engine.rs` | Rhai のエンジン。スクリプトから呼べる関数を登録し、呼ばれたら要求を送って返事を待つ |
| UI | `scripting/mod.rs`, `scripting/ui.rs` | `ScriptRun` リソース、プロパティ欄のエディタ、「PLC連携」ウィンドウの実行操作 |

`runner.rs` と `controller.rs` は Bevy に依存しない(Rhai には依存する)。

## 待ちのしくみ

`wait(0.5)` や `move_joint` はスクリプトの途中で止まって、シミュレーションの時間が進むのを待つ必要がある。
Rhai には途中で止めて後から再開するしくみがないので、スクリプトごとに専用のスレッドで動かし、チャネルで要求と返事をやりとりする。

1. スクリプトが関数(`get`・`set`・`move_joint`・`wait` など)を呼ぶと、要求 (`Request`) を送って返事 (`Reply`) を待つ
2. シミュレーター側は毎スキャン `ScriptRunner::step(host, now)` を呼び、要求を1つずつ処理する
   - 信号の読み書きのようにすぐ終わるものは、その場で返事をして次の要求を待つ
   - `wait`・関節の移動・`wait_signal` は返事を保留し (`Pending`)、時刻や条件が満たされたスキャンで返事をする
3. スクリプトが最後まで走るかエラーになると `Finished` を送る

シミュレーター側は返事を送ったら次の要求が来るまで待つので、スクリプトとシミュレーションは必ず交互に進み、結果は毎回同じになる。
`wait` を入れずに信号を見続けるループ (`while !get("x") {}`) でも、1スキャンで処理する要求を 1000 件までにしているので画面は固まらない。
要求を出さずに 2 秒以上計算し続けたら、無限ループとみなして止める。`ScriptRunner` を落とすと、Rhai の `on_progress` で計算中のスクリプトも止まる。

## 1スキャンの流れ

`PlcSession::scan_with` が、模擬 PLC の代わりに `ScriptController::scan` を呼ぶ。

1. 設備モデルの現在値から入力を作る(出端・戻端・現在位置・位置決め完了)
2. 時刻を `dt` 進め、各スクリプトを `step` する。センサーは前のフレームの `SensorStates` を使う
3. スクリプトが書いた出力を指令値として設備モデルに渡し、`dt` 秒ぶん動かす

関節の移動 (`move_joint`) は、シリンダなら出指令のビット、直動・回転なら指令位置のワードを書くだけで、動く速さは模擬 PLC と同じ設備モデルで決まる。
着いたかどうかは、シリンダは出端・戻端のスイッチ、直動・回転は現在値と指令値の差で判断する。

## 名前の解決

| 関数 | 探す順 |
| --- | --- |
| `get` / `wait_signal` | I/O 一覧のビット → センサー名 → 内部信号 |
| `set` | I/O 一覧の出力ビット(入力・センサー・ワードはエラー)→ それ以外は内部信号として作る |
| `joint` / `move_joint` | タイミングチャートのアクチュエータ名。可動範囲があれば範囲外はエラー |

自作部品の中のスクリプト(いちばん近い祖先に `Node::custom_part` があるもの)は、その部品の名前の頭(例 `プッシャー 1/`)を `ScriptSource::scope` に持つ。
上のどの関数も、頭を付けた名前が I/O・センサー・アクチュエータにあればそちらを使い、なければ書いたとおりの名前で探す。内部信号には頭を付けない(部品どうしの合図に使えるように)。
