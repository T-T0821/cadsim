# ライン連携のしくみ

工程シミュレーション・AGV・ワーク搬送 (3D のコンベア)・作業者・タイミングチャート・安全機器を、1つの時計で一緒に動かすしくみです。
使い方は README の「工程・AGV・安全機器をつないでラインとして動かす」を見てください。

## 置き場所

| 層 | 場所 | 中身 |
| --- | --- | --- |
| ドメイン | `cadsim_core::flow::sim` | ライン連携の口: `Simulation::link`・`take_events`・`pick_up`・`deliver`・`set_source_enabled` |
| ドメイン | `cadsim_core::line::coupler` | 工程の出来事と AGV・コンベアの出来事の受け渡し (`LineCoupler`) |
| ドメイン | `cadsim_core::line::stepper` | 工程・AGV・ワーク搬送を同じ時間だけ少しずつ進める (`step`)、つなぎ方の設定の確かめ (`link_problems`・`conveyor_problems`) |
| ドメイン | `cadsim_core::conveyor::sim` | ライン連携の口: `ConveyorSim::drive_sources`・`feed_external`・`take_events` |
| ドメイン | `cadsim_core::line::signals` | PLC とやりとりする信号表と、PLC → 設備の値 (`LineInputs`) |
| ドメイン | `cadsim_core::line::workpieces` | 3D に描くワークの位置 (積む・渡る・置き場所の決め方) |
| UI | `src/line/mod.rs`・`view.rs`・`panel.rs` | 毎フレームの進め方、3D のワーク、「ライン連携」ウィンドウ |
| UI | `src/conveyor/mod.rs` | `WorkState::start_line`・`with_line` (ワーク搬送をラインの時計で進めるための入力をそろえる)、`TimeMap` |

## 1つの時計

ライン連携の再生中は、毎フレーム `実時間の経過 × 倍速` 秒だけ、次の順に進めます。

1. 止める条件を見る。安全停止中 (`SafetyState::is_stopped`) か、PLC の「ライン.運転」が OFF なら何も進めない。
2. 工程シミュレーション・AGV・ワーク搬送を、最大 0.25 秒ずつ交互に進める (`stepper::step`)。1 歩ごとに出来事を受け渡す。
3. 作業者の時計 (`FloorClock::time`) を同じだけ進める。作業者と AGV は安全機器の検知の対象なので、このあと同じフレームで検知が走る。
4. タイミングチャートの再生 (`Playback`) を、ラインと同じ倍速で流す。「チャート起動」の工程があれば、その工程が加工を始めたときだけ頭から再生する。

工程シミュレーションと「作業者・AGV」パネルのそれぞれの再生フラグは、連携中は毎フレーム下ろしておき、二重に進まないようにしています。
工程モデル・AGV の経路・ワーク搬送の設定が途中で変わったら、それまでの状態に意味がなくなるので止めて、次の再生で最初から回します。

## 工程と AGV の受け渡し

工程モデルの要素に `carrier: Some(AgvCall { from, to })` を付けると、その要素は送り出せるワークができても自分では下流へ動かしません。

```text
工程シミュレーション            LineCoupler                 AgvSim
  ワークができた ── CarrierNeeded ──▶ 荷札 tag を振る ── request(from, to, tag) ──▶ 配車
                                                                         積み込み完了
  pick_up(要素) ◀──────────────── PickedUp{tag} ◀──────────────────────────┘
  (空いた所に上流から次が入る)                                            荷降ろし完了
  deliver(荷) ◀─────────────────── Delivered{tag} ◀─────────────────────────┘
  (送り先が空いていなければ空くまで待つ)
```

- 積まれている間のワークは工程シミュレーションの「運搬中」に入り、仕掛数に数えます。
- 降ろし先へ行けずに AGV が搬送をあきらめたとき (`Abandoned`) は、ワークがなくならないように、その場で送り先へ入れます。
- AGV のシミュレーションがないときは、頼んだ搬送はすぐ届いたことにします。
- 工程シミュレーションのウィンドウだけで回すとき (`Simulation::run` や連携していない `advance`) は `carrier` を見ません。いままでどおりすぐ下流へ送ります。

## 工程とコンベアの受け渡し

工程モデルの要素に `conveyor: Some(投入口の id)` を付けると、送り出しをワーク搬送 (docs/conveyor.md) の投入口から流します。
受け渡しは AGV と同じ形で、`LineCoupler` は AGV の代わりに `LineCommand::FeedConveyor { source, tag }` を出します。

```text
工程シミュレーション            LineCoupler                     ConveyorSim
  ワークができた ── CarrierNeeded ──▶ 荷札 tag ── feed_external(投入口, tag) ──▶ 出す場所が空くまで待つ
                                                                          投入口から出た
  pick_up(要素) ◀──────────────── PickedUp{tag} ◀── Fed{tag} ───────────────────┘
                                                                          排出口・排出端から出た
  deliver(荷) ◀─────────────────── Delivered{tag} ◀── Discharged{tag} ──────────┘
```

- 工程から送り込む投入口 (`drive_sources`) は、間隔ではワークを出しません。頼まれた順に、出す場所 (コンベアの始端か部品の上) が空いた刻みで 1 つずつ出します。
  投入口がふさがっている間、工程は送り出せずに「詰まり」になります。
- 流したワークには荷札 (`Work::tag`) が付きます。グリッパで掴み替えたり別のコンベアに載せ替えたりしても荷札は残り、どこから出ても下流へ入ります。
  置き場があふれて古いワークを消したときも、ワークがなくならないよう `Discharged` を出します。
- 外から入れたワークは時刻 0 からの計算し直しでは再現できないので、ライン連携の間は `ConveyorSim::seek` を使わず、`advance_to` で前へだけ進めます (`WorkState::linked` の間は、チャートの再生位置で計算し直す `update_works` は何もしない)。
  ワーク搬送の時刻はラインの時刻と同じで、安全停止中や運転 OFF の間はコンベアも止まります。
- グリッパと動く台の動きはタイミングチャートから求めます。チャートは「チャート起動」で途中から頭に戻るので、毎フレームそのときの再生位置 `Playback::time` から同じ速さで進むとみなして、
  ワーク搬送の時刻をチャートの時刻に写します (`TimeMap { from: ワーク搬送の時刻, base: 再生位置, rate: チャートの速さ / ラインの速さ }`)。
- ワーク搬送の設定 (`ConveyorConfig`) が空なら、コンベアに頼んだ搬送はすぐ届いたことにします。投入口が見つからない・ワークが出ていく先がない設定は、「ライン連携」ウィンドウに `conveyor_problems` の説明を出します。
- 工程からコンベアへ送り込んでいるときは、「チャート起動」の工程があってもタイミングチャートを流し続けます (グリッパがチャートで動かないとワークが進まず、加工も始まらないため)。加工開始で頭に戻すのは同じです。
- 工程の送り出しに使わない投入口は、ライン連携の間もラインの時刻で間隔どおりにワークを出します。

## 信号表

信号は工程モデルの要素の名前から毎回作ります。保存はしません。番号はタイミングチャートのアクチュエータの信号 (0 番台・100 番台) と重ならないよう、次の先頭から表の順に詰めて振ります。

| 領域 | 先頭 | 中身 |
| --- | --- | --- |
| 設備 → PLC のビット | 200 | `ライン.運転中`・`安全.停止`、工程ごとの `稼働`・`詰まり`・`故障`・`在荷`、バッファの `満杯`、`AGV<n>.搬送中` |
| 設備 → PLC のワード | 200 | `ライン.排出数`、バッファの `数`、`AGV.搬送待ち`、ワーク搬送の投入口があれば `コンベア.投入数`・`排出数`・`仕掛数` |
| PLC → 設備のビット | 300 | `ライン.運転`、生成ごとの `投入許可` |

コンベアの数 (`ConveyorCounts`) は、ワーク搬送 (docs/conveyor.md) の投入口があるときだけワードの最後に足します。
ワーク搬送を使うかどうかで工程・AGV の信号の番号がずれないようにするためです。値は `src/line/mod.rs` の `read_conveyor` が
`ConveyorSet::Works` の後に `WorkState` から読んで `LineState` に覚え、次のフレームの信号表で使います (1 フレーム遅れ)。
コンベアのワークはタイミングチャートの再生に合わせて流れ、チャートはライン連携の時計に付いて進むので、ラインと同じ時間で数えられます。

PLC → 設備の値は `LineInputs` に持ち、名前で書けます (`LineInputs::set`)。名前が表にない信号は ON とみなすので、PLC をつながなくてもラインは動きます。

PLC 連携 (docs/plc.md) とは `src/line/mod.rs` の `exchange_plc` でつなぐ。毎フレーム信号表を PLC 連携の I/O に書き (`Plc::exchange_line`)、外部 PLC かログ再生が PLC → 設備の信号を書いているときは、その値を `LineInputs` に写す。そのあいだは画面での切り替えはできない。
投入許可が OFF の間は、生成は次のワークを出しません。出す時刻を過ぎてから ON に戻ると、すぐに 1 個出します。

## 3D のワーク

- 置き場所は、3D の部品を対応付けた要素はその部品の上面の中心、ないときは AGV で送り出す要素なら積み込みのステーション、AGV で届く先の要素なら荷降ろしのステーションの台 (高さ 700 mm) の上です。どちらもない要素は描きません。
- 設備の中のワークは 3×3 の格子に積み、あふれたら上の段へ。
- AGV を使わずに設備から設備へ移ったワークは、1.5 秒 (ラインの時間) かけて弧を描いて移ります。その間は届く先の山には数えません。
- AGV に積まれているワークは、AGV の上に描きます。

どれもギズモの立方体で描き、メッシュは作りません。
