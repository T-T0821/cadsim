# 画面での動作確認の自動化 (UI チェック)

単体テストは計算の正しさを確かめますが、「ボタンを押したら窓が開く」「再生したら部品が動いて見える」といった
画面での振る舞いは確かめられません。UI チェックは、手順書に書いた操作をアプリに流して画面を撮り、
前に撮った基準画像と見比べて、画面が変わってしまった所を見つけます。

## 流し方

```sh
cargo ui-check                                  # tests/ui の手順書をすべて流す
cargo ui-check --only chart                     # 名前に chart を含む手順書だけ
cargo ui-check tests/ui/03_timing_chart.scenario
cargo ui-check --update                         # 基準画像を今回の写真で置き換える
tools/ui_check.sh                               # Linux: 画面がなければ仮想画面 (Xvfb) で流す
```

`cargo ui-check` は `cargo run --locked -- --ui-check` の別名です (`.cargo/config.toml`)。
Windows のリリースビルドはコンソールを持たず結果の要約が端末に出ないので、開発ビルドで動かします。
流している間はアプリの窓が手順書ごとに開いて閉じます。マウスやキーボードには触らないでください。

| オプション | 意味 |
| --- | --- |
| `--ui-check [手順書かフォルダ]` | 流す手順書。省略すると `tests/ui` の `*.scenario` をすべて |
| `--only 名前` | 名前にこれを含む手順書だけを流す (何回でも書ける) |
| `--update` | 比べずに、今回の写真を基準画像にする |
| `--out フォルダ` | 結果の置き場所。既定は `target/ui-check` |
| `--baseline フォルダ` | 基準画像の置き場所。既定は `tests/ui/baseline/<OS>` (`linux` / `windows` / `macos`) |
| `--timeout 秒` | 手順書 1 つの制限時間。既定は 900 秒 |

全部合格なら終了コード 0、どれかが違えば 1、手順書が見つからないなどで流せなければ 2 を返します。
端末には手順書ごとに `OK` / `NG` と写真ごとの判定が出ます。

### 結果の見かた

`target/ui-check/index.html` をブラウザで開くと、手順書ごとの結果が一覧になります。
手順書の名前を押すと、写真ごとに「基準」「今回」「差分」が並びます。差分画像では、違う画素が赤、
比べない領域が青で塗られます。

```text
target/ui-check/index.html                   一覧
target/ui-check/<手順書>/report.html          写真ごとの比較
target/ui-check/<手順書>/actual/<名前>.png     今回の写真
target/ui-check/<手順書>/expected/<名前>.png   基準画像の写し (違ったときだけ)
target/ui-check/<手順書>/diff/<名前>.png       差分画像
target/ui-check/<手順書>/log.txt              アプリのログ (落ちたときの手がかり)
```

### 違いが出たら

1. 報告書で差分を見て、意図した変更 (画面の手直しなど) か、壊れたのかを判断します。
2. 意図した変更なら `--update` を付けて流し直し、基準画像を置き換えてコミットします。
3. 壊れていたら直して、もう一度流します。

基準画像がない写真は、その回の写真がそのまま基準になります (判定は合格)。
初めて流す OS や、手順書に写真を足したときはこうなります。

## しくみ

- 手順書ごとにアプリを起動し直します。前の手順書の状態を持ち越しません。
- 設定ファイル (見た目・ミッションの進み・自作部品・AI の設定) は、毎回空のフォルダ
  (`target/ui-check/<手順書>/config`) から始めます。使う人の設定に左右されず、使う人の設定も書き換えません。
  `CADSIM_CONFIG_DIR` という環境変数でこの場所を差し替えています。生成 AI の API キーの環境変数は渡しません。
- 時計は 1 フレーム = 1/60 秒で進めます (egui の時計も同じ)。描画が速くても遅くても、アニメーションや通知が同じ場面で撮れます。
  FPS や計算にかかった時間のような毎回変わる数は `--` と表示します。ミッション達成の紙吹雪は描きません
  (続けて達成したときに降り始めが入れ替わり、写真が毎回ずれやすいため。お祝いの表示とミッションカードは出します)。
- 読み込み・保存・干渉部分の計算・形状の簡略化・動画の書き出しのような、別スレッドで進む処理の途中は、
  時計を止めて手順も進めません。処理が何フレームで終わっても、その間は「なかったこと」になるので、
  どの手順も毎回同じ場面で実行されます。撮った写真が届くのを待つ間も同じです。
- 入力は、本物のマウス・キーボードと同じ Bevy のメッセージ (`CursorMoved`・`MouseButtonInput`・`KeyboardInput` など) として流します。
  egui の画面も、ショートカットも、3D ビューのクリックも、手で触ったときと同じ経路を通ります。
- ボタンなどは egui のアクセシビリティ情報 (AccessKit) の表示名と位置で探します。座標を書かなくてよいので、
  画面の配置が変わっても手順書を直さずに済むことが多いです。
- 色の差が少し (R・G・B どれも 24 段階以内) の画素は同じとみなし、違う画素が全体の 0.2% 以内なら合格にします。
  GPU やドライバの違いで輪郭の色が少しずれる程度は通ります。

コードの置き場所:

| 層 | 場所 | 中身 |
| --- | --- | --- |
| ドメイン | `cadsim_core::ui_check` | 手順書の読み取り (`scenario`)、1 フレームずつの進め方 (`runner`)、部品の探し方 (`widget`)、画像の比べ方 (`compare`)、判定 (`report`) |
| アダプター | `cadsim_io::ui_check` | PNG の読み書き、結果の JSON、報告書の HTML |
| UI | `src/ui_check/mod.rs` | Bevy のシステム。画面の様子を集めて runner に渡し、返ってきた入力を流して写真を撮る |
| UI | `src/ui_check/suite.rs` | 手順書ごとにアプリを起動し直して流し、一覧を書く (Bevy なし) |

### 基準画像と環境

3D の描画は GPU・ドライバ・OS で少しずつ違うので、基準画像は OS ごとに分けて置きます。
リポジトリには Linux の仮想画面 (Xvfb) とソフトウェア描画 (Mesa の lavapipe) で撮った `tests/ui/baseline/linux` を入れています。
Windows や Mac で初めて流すと、その回の写真が `tests/ui/baseline/windows` などに基準として保存されます。

Linux で画面のないマシンでは `tools/ui_check.sh` を使います。`xvfb-run` と `mesa-vulkan-drivers` が要ります
(Ubuntu なら `sudo apt install xvfb mesa-vulkan-drivers`)。

## 手順書の書き方

手順書は `tests/ui/<番号>_<名前>.scenario` に置きます。1 行に 1 つの操作を書き、`#` から行末まではコメントです。
文字列は `"…"` で囲みます (中の `"` は `\"`)。座標はウィンドウの左上からの位置 (ウィンドウは 1440×900) です。

```text
# サンプルを開いて部品を選び、元に戻す
wait_loaded                      # 起動時のサンプルの読み込みを待つ
wait 60                          # カメラの動きが落ち着くまで 60 フレーム待つ
click "ベース"                    # ツリーの「ベース」をクリック
expect "選択: "                   # ステータスバーに選択中の部品が出ている
screenshot 01_selected
key ctrl+z
screenshot 02_undo
```

| 操作 | 意味 |
| --- | --- |
| `open パス` | ファイルを開く (`.cadsim` は開き直し、STEP などは取り込み)。パスはリポジトリのフォルダから。`saved/名前` は、この手順書の中で保存したファイル |
| `wait フレーム数` | 待つ (60 フレーム = 1 秒) |
| `wait_loaded` | 読み込み・保存・動画の書き出しが終わるまで待つ |
| `click "表示名" [何番目]` | 表示名の部品をクリックする。表示名が同じものが複数あれば上から何番目か |
| `double_click "表示名" [何番目]` | ダブルクリック |
| `hover "表示名" [何番目]` | マウスを乗せる (ツールチップやサブメニューを出す) |
| `click_at x y` | 座標をクリックする (3D ビューの部品など、表示名がないもの) |
| `drag x1 y1 x2 y2 [left/right/middle]` | 押したまま動かして離す |
| `scroll x y 量` | ホイールを回す (正で拡大) |
| `key ctrl+z` | キーを押して離す。`ctrl` `shift` `alt` と、`a`〜`z` `0`〜`9` `f1`〜`f12` `enter` `esc` `space` `tab` `backspace` `delete` `home` `end` `left` `right` `up` `down` |
| `type "文字"` | 入力欄に文字を打つ (先に入力欄をクリックしておく) |
| `expect "表示名"` | 画面にあることを確かめる (なければ失敗) |
| `expect_not "表示名"` | 画面にないことを確かめる |
| `mask x y 幅 高さ` | この後の写真で比べない領域を足す (毎回変わる数字など) |
| `clear_masks` | 比べない領域を取り消す |
| `screenshot 名前` | 画面を撮って基準画像 `名前.png` と比べる |
| `dump_widgets 名前` | 画面の部品の表示名と位置を `target/ui-check/<手順書>/名前.txt` に書き出す |

表示名は、まったく同じものを優先し、なければ表示名を含むものを探します (`click "開く"` は「開く…  (Ctrl+O)」にも当たります)。
窓のタイトル (「部品ライブラリ」「PLC連携」など) をクリックすると、窓をたたんだり開いたりします。
開いたばかりの窓の中身のように動いている途中の部品は、2 フレーム続けて同じ場所に止まってからクリックします。
見つからないときは 3 秒 (180 フレーム) 待ってから失敗にし、似た表示名を報告に添えます。
手順が失敗したときは、そのときの画面 (`failure.png`) も報告書に載ります。
どんな表示名があるか分からないときは、手順書に `dump_widgets 一覧` を書いて流し、書き出された一覧を見てください。

OS の窓 (ファイルを選ぶダイアログなど) は操作できません。そのため自動確認の途中は、プロジェクトの「名前を付けて保存」と
動画の書き出しでダイアログを出さず、`target/ui-check/<手順書>/saved/` に書きます (`project.cadsim`・`simulation.gif` など)。
保存したプロジェクトは `open saved/project.cadsim` で開き直せます。「開く…」のダイアログを出す操作の代わりには `open` を使ってください。
ほかの書き出し (図面・部品表・Excel など) はまだダイアログを出すので、手順書に入れないでください。
