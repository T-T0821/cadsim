# 物理演算の設計

重力・接触・摩擦で部品(ワーク)を動かす機能と、ケーブル・ホースの紐モデルのしくみです。使い方は README の「物理演算でワークを流す」を見てください。

## 層の分け方

[architecture.md](architecture.md) の4層に合わせて分けています。ドメインとユースケースは `crates/cadsim_core/src/physics/`、残りはアプリ本体の `src/physics/` です。アダプターの2つは Bevy に依存しないので、`cadsim_io` ができたらそのまま移せます。

| ファイル | 層 | 内容 | 依存 |
| --- | --- | --- | --- |
| `settings.rs`(core) | ドメイン | 部品ごとの物理の設定 `PartPhysics`(振る舞い・当たり判定の形・摩擦・反発・密度・ベルト)、単位と重力 | `glam` |
| `cable.rs`(core) | ドメイン | ケーブル・ホースの紐モデル `CableState` と判定 `CableReport` | `glam` |
| `world.rs`(core) | ユースケース | 部品 → 剛体の変換 `part_body`、一定刻みの進行 `PhysicsRun`、エンジンのポート `PhysicsEngine` | `glam` |
| `rapier.rs` | アダプター | `PhysicsEngine` の Rapier 実装 | `rapier3d` |
| `records.rs` | アダプター | `.cadsim` に書く形(serde) | `serde` |
| `mod.rs` / `panel.rs` / `sample.rs` | UI | Bevy のシステム、egui のパネル、サンプルライン | Bevy・egui |

Bevy 用の物理プラグイン(avian3d / bevy_rapier)ではなく、Bevy に依存しない `rapier3d` を使っています。物理の世界を ECS の外に置けるので、ユースケースとアダプターを Bevy なしで単体テストでき、`cadsim_io` にもそのまま移せます。

## 部品の振る舞い

部品(ノード)ごとに `PartPhysics` を持ち、プロジェクトファイルに保存します。既定は「機構で動く」で、何も設定しなければ物理演算を始めても見た目は変わりません。

| 振る舞い | Rapier の剛体 | 位置の決まり方 |
| --- | --- | --- |
| 動かない | fixed | 設計位置のまま(タイミングチャートの動きも無視) |
| 機構で動く | kinematic (位置ベース) | 毎刻み、タイミングチャートの位置を目標として与える。フレームの間は補間するので、押し板が滑らかに押す |
| 物理で動く | dynamic + 連続衝突判定 | 重力・接触・摩擦。開始時の位置から物理が決める |
| 当たらない | 作らない | 今までどおり |

非表示の部品は物理の世界に入れません。

## 当たり判定の形

| 形 | 作り方 | 向いているもの |
| --- | --- | --- |
| 箱 | 箱の部品はパラメータそのもの、取り込んだ部品は外接箱 | ワーク、板、ガイド |
| 凸包 | 表示用メッシュの頂点の凸包(Rapier が計算) | 取り込んだワーク(くぼみは埋まる) |
| 凸分解 | 表示用メッシュを V-HACD で凸の立体いくつかに分ける | シュートの溝、トレイなどくぼみのあるもの。開始時に時間がかかる |
| メッシュ | 表示用メッシュの三角形そのもの | 動かない・機構で動く設備 |

「自動」は、箱の部品なら箱、取り込んだ部品は物理で動くなら凸包、それ以外はメッシュです。Rapier ではメッシュどうしは当たらないので、物理で動く部品にメッシュは使いません(凸包に置き換えます)。

取り込んだ部品の表示用メッシュは面ごとに頂点が分かれているので、`indexed_mesh` で重なった頂点をまとめてから渡します。

## ベルトコンベア

ベルト自体は動かさず、ベルトに触れている接触点の「接線方向の目標相対速度」(`SolverContact::tangent_velocity`)をベルト速度にします。Rapier の接触フック(`PhysicsHooks::modify_solver_contacts`)で書き換え、ベルトの速度は collider の `user_data` に f32 × 3 で詰めて持たせます。ワークは摩擦でベルト速度まで加速し、ストッパに当たると摩擦に逆らって止まります。

## 時間の進め方

- 刻みは 1/120 秒の固定(`STEP_DT`)。フレームの長さが揺れても、結果は刻みの数で決まります。
- 物理で動く剛体は眠らせません(Rapier の「止まった」とみなす速さは単位に比例して大きくなり、ベルトで一定速度で流れるワークまで眠ってしまうため)。接触を予測する距離も 2 mm 相当に縮めています(既定の 2 cm だと、ベルト面のすぐ下に下がったストッパの角でワークが止まる)。
- 1 フレームに進める刻みは 8 までで、それより遅れた分は捨てます(重いときに固まり続けないように)。
- タイミングチャートがあるときは、物理パネルの ▶ でチャートの再生も始め、チャートの一時停止に合わせて物理も止めます。チャートの ⏮ 先頭へ で物理も設計位置に戻ります。
- 長さの単位は Rapier の `length_unit` に渡し、重力は 9.81 m/s² を単位に合わせて換算します(mm なら 9810 mm/s²)。密度は g/cm³ で受け取り、kg / モデル単位³ にします。

## ケーブル・ホース

両端を部品(またはワールドの点)に付けた紐を、点を鎖のようにつないだもの(位置ベースの動力学、Verlet 積分)で表します。

- 点の数は直径の 2 倍間隔を目安に 8〜48 区間。
- 1 刻みで、慣性と重力 → 隣どうしの距離の拘束 → 1 つ飛ばしの点を少しまっすぐにする拘束(曲げにくさ) → 部品の外接箱からの押し出し、を 24 回繰り返します。端の 2 区間は、端を付けた部品や、端が埋まっている部品(継手を差し込んだ部品)の中にあってよいことにしています。
- 紐は物理演算を止めていても毎フレーム進めます。タイミングチャートの再生だけでも、可動部に引かれる様子が見られます。
- 判定:
  - 曲げ半径 … 隣り合う 3 点を通る円の半径。許容より小さい点を赤く描きます。
  - 長さ不足 … 両端の距離 ÷ 長さ が 0.999 を超えたら、引っ張られているとみなして全体を赤く描きます。
  - 接触 … 外接箱に触れている部品の一覧。
- 当たり判定は部品の外接箱(箱の部品は回転した箱そのもの)なので、くぼみのある部品の中を通す配線は正確ではありません。

## 性能

`sample.rs` のテスト `works_flow_into_the_bin` が、サンプルライン(ワーク 100 個)を 30 秒分流し、1 フレームあたりの計算時間を表示します。リリースビルドでは 60 fps の予算(16.7 ms)に収まることを確かめています。

```sh
cargo test --release --locked works_flow_into_the_bin -- --nocapture
```

描画を含めた画面の FPS は、サンプルラインを流しながら `--bench` で測れます。

```sh
cargo run --release -- --physics --bench 20
```

物理の計算はリリースビルドでワーク 100 個あたり 1 フレーム 0.4 ms ほどです。GPU の無いクラウド環境(ソフトウェア描画)では描画が律速になり 12 fps ほどでしたが、これは物理なしの 7 部品のサンプル(5 fps 前後)より速く、描画側の制約です。
