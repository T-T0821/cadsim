# PLC 連携(仮想立ち上げ)の設計

タイミングチャートの時刻表の代わりに、PLC の出力でアクチュエータを動かし、端のスイッチや現在位置を PLC の入力に返す。

## 層の分け方

[architecture.md](architecture.md) に合わせ、`src/plc/` の中で層を分けている(ワークスペース化したら `cadsim_core::domain::plc` などへ移す)。

| 層 | ファイル | 内容 |
| --- | --- | --- |
| ドメイン | `domain/io.rs` | 信号 (`Point`)、割り付け表 (`IoTable`)、現在値 (`IoValues`)。ワードの符号付き 16 ビットへの変換 |
| ドメイン | `domain/plant.rs` | 設備モデル。出力 → 指令値 → 一定速度で近づく → 端のスイッチ・現在位置 |
| ドメイン | `domain/io_csv.rs` | I/O 対応表の CSV 書き出しと読み戻し(信号ごとの個別設定 `PointSettings`)|
| ドメイン | `domain/log.rs` | PLC ログ (CSV) の読み込みと、時刻 t の出力の値 (`PlcLog`) |
| ドメイン | `domain/sequencer.rs` | 内蔵の模擬 PLC。チャートのステップを I/O で実行 |
| ユースケース | `usecase.rs` | `PlcSession`: 1スキャン分の処理、ログ再生の位置 (`LogPlayer`)。外部 PLC との通信はポート `PlcLink` で受け取る |
| アダプター | `adapter/opcua.rs` | `PlcLink` の OPC UA クライアント実装([async-opcua](https://crates.io/crates/async-opcua)、MPL-2.0)|
| アダプター | `adapter/modbus.rs` | `PlcLink` の Modbus TCP 実装([tokio-modbus](https://crates.io/crates/tokio-modbus))|
| ドメイン | `domain/device_map.rs` | 信号を三菱 PLC のデバイス (M100、D0 など) に置く割り当て (`DeviceMap`) と、その問題の検出 |
| ドメイン | `cadsim_core::melsec` | 三菱 PLC のデバイスの種類 (`Device`) と1点 (`DeviceRef`)。X・Y・B・W は 16 進数の番号 |
| アダプター | `cadsim_io::slmp` | SLMP の電文 (`frame`)、TCP / UDP のクライアント (`client`)、テスト用の PLC (`mock`)。外部のライブラリは使わない |
| アダプター | `adapter/slmp.rs` | `PlcLink` の SLMP 実装 (`SlmpLink`)。通信スレッドと、I/O 表 ↔ デバイスの読み書き |
| UI | `mod.rs`, `ui.rs` | `Plc` リソース(`PlcSession` の包み型)、Bevy のシステム、「PLC連携」ウィンドウ |

## 毎フレームの流れ

`MotionSet::Drive`(`MotionSet::Pose` の中)で `PlcSession::scan` を呼ぶ。

1. 設備モデルの現在値から入力を作る(出端・戻端・現在位置・位置決め完了)
2. PLC を1スキャン動かす(模擬 PLC)か、外部 PLC と入出力を交換する(`PlcLink::exchange`)
3. 出力を指令値として設備モデルに渡し、`dt` 秒ぶん動かす
4. アクチュエータの現在値から `part_poses_from_values` で部品の動きを求め、`SimulationPose` に書く

PLC 連携中は `update_pose`(時刻表での再生)とギズモを止める(`plc_active`)。表示・干渉チェックはチャート再生と同じ `SimulationPose` を使う。

## 信号と番号

| アクチュエータ | 出力(PLC → 設備) | 入力(設備 → PLC) |
| --- | --- | --- |
| シリンダ | 出(ビット、シングルソレノイド) | 出端、戻端(ビット) |
| 直動軸・回転テーブル | 指令位置(ワード) | 現在位置(ワード)、位置決め完了(ビット) |

- ビットはコイル、ワードは保持レジスタ。4つの領域(出力ビット・出力ワード・入力ビット・入力ワード)の先頭番号から、アクチュエータの並び順に詰めて振る。同じ番号に2つの信号が来たら警告する。
- ワードは符号付き 16 ビット。直動は 1 = 0.1 (mm なら 0.1 mm、±3276.7)、回転は 1 = 0.1°。範囲外は端に丸める。
- 設備モデルの速度: シリンダは「出端まで既定の動作時間」、直動・回転はチャート内でいちばん速い動作の速度。

### ライン連携の信号

ライン連携 (docs/line.md) の信号表は、アクチュエータの信号の後ろに `Point::LineInput` / `LineInputWord` / `LineOutput` として並ぶ。
番号はライン連携の信号表の番号 (設備 → PLC のビット・ワードは 200 番台、PLC → 設備のビットは 300 番台) をそのまま使い、
CSV で個別の番号・OPC UA ノード・ログ列名を決められる (保存では `actuator` の欄に信号表の番号を入れる)。

- 毎フレーム、ライン連携のシステムが信号表を作って `PlcSession::set_line_signals` で I/O に書く。信号の並びが変わったら I/O 表を作り直す。
- PLC → 設備の値 (`PlcSession::line_outputs`) は、外部 PLC とつないでいるときとログ再生のときだけラインに写す。内蔵の模擬 PLC はライン連携の信号を書かないので、そのときは画面の切り替えに任せる。
- 信号表の番号は工程モデルの要素の並びから振るので、要素を足したり消したりすると後ろの番号がずれる。CSV で個別に決めた設定も番号で覚えているため、そのときは CSV を見直す。

## I/O 対応表の CSV

列は `信号,向き,種類,番号,スケール,OPC UAノード,ログ列名`(ログ列名のない古い CSV も読める)。Excel で開けるよう UTF-8 の BOM と CRLF で書く。
読み込みは「信号」で始まる見出し行を探し、その下の行を信号名で突き合わせて `AddressPlan::custom`(信号 → `PointSettings`)に入れる。
番号・スケール・ノードの空欄は自動の値を使う。向き・種類は確認用で、読むときは使わない。
表にない信号名と読めない行は飛ばして、件数と一緒に画面に出す。個別設定はアクチュエータ id で持つので、名前を変えても残る。

## 内蔵の模擬 PLC

実機のステップラダーと同じく、1スキャンごとに「今のステップの動作を出力に書く → 入力で全動作の完了を確かめる → 完了後タイマーが過ぎたら次へ」。
軸の完了は、位置決め完了が前の指令位置のものでないよう、現在位置が指令位置に一致していることも確かめる。

## Modbus TCP

- シミュレーターがクライアント(マスター)。出力のコイル・保持レジスタを読み、入力のコイル・保持レジスタを書く(FC1 / FC3 / FC15 / FC16)。
- 連続した番号は1回の要求にまとめる(1要求 120 点まで)。
- 通信は別スレッド。画面側は最新の要求を共有メモリに置き、届いた読み値を写すだけで待たない。切れたら 1 秒ごとにつなぎ直す。
- テストでは tokio-modbus のサーバーを PLC の代わりに立てて、読み書きが届くことを確かめている。

## 三菱 PLC (SLMP)

三菱電機の PLC (MELSEC iQ-R / iQ-F / Q / L) と、ゲートウェイなしに SLMP (MC プロトコル) でつなぐ。

- シミュレーターがクライアント。出力の信号を置いたデバイスを一括読出し (0401) で読み、入力の信号を置いたデバイスに一括書込み (1401) で書く。
  サブコマンドは Q/L 互換のビット単位 0001・ワード単位 0000 (iQ-R も受け付ける)。同じデバイスの連続した番号は1回の要求にまとめ、1要求 480 点で分ける。
- 3E / 4E フレーム、バイナリ / ASCII コード、TCP / UDP を選べる。宛先は自局 (ネットワーク 00・PC FF・要求先ユニット 03FF・局番 00)、監視タイマは待ち時間 1 秒に合わせて 4 (250 ms 単位)。
  4E では要求ごとにシリアル番号を増やし、番号の違う応答 (遅れて届いた前の応答) は捨てる。
- TCP は電文の先頭 (データ長の欄まで) を読んでから残りを読む。UDP は 1 データグラム = 1 電文。
- 異常の終了コード (C059 など) は、コードと意味を通信の状態に出してつなぎ直す。
- デバイスは X・Y・M・L・B (ビット) と D・W・R (ワード)。電文のデバイスコードは `frame::device_code`。ASCII では X・Y・B・W の番号を 16 進数、それ以外を 10 進数で書く。

### 信号とデバイスの対応

I/O 表の番号はコイル・保持レジスタの番号のまま。4つの領域ごとに「先頭の信号を置くデバイス」(`DeviceArea`) を決め、
`デバイスの番号 = 先頭のデバイス番号 + (信号の番号 − 領域の先頭番号)` とする (`DeviceMap::locate`)。
領域の先頭番号は I/O 表を作ったときのもの (`IoTable::starts`) を使う。

- 初期値は 出力ビット M0、出力ワード D0、入力ビット M100、入力ワード D100。I/O 表の初期値と同じなので、番号がそのままデバイスの番号になる。
- ライン連携の信号 (200 番台・300 番台) も同じ式で置く (初期値なら M200〜・M300〜・D200〜)。
- 領域の先頭番号より前の番号 (CSV で個別に決めたものなど) は置けないので、画面に警告を出して通信しない。同じデバイスに2つの信号が来たときと、ワードの領域にビットデバイスを選んだときも警告する。
- ワードは Modbus と同じく符号付き 16 ビットで、I/O 表のスケールで換算する。

### テスト

`cadsim_io::slmp::mock::MockPlc` が、デバイスメモリを持つ SLMP サーバー (TCP / UDP、3E / 4E、バイナリ / ASCII) になる。
電文はマニュアルの例 (D100 から 3 ワード読むなど) とバイトごとに比べ、クライアントとアプリ側の `SlmpLink` は `MockPlc` 相手に全部の組み合わせで読み書きを確かめている。
実機での確認はまだしていない。

## OPC UA

- I/O 表で「OPC UAノード」を決めた信号だけを扱う。PLC の出力のノードはサブスクリプションで購読し、設備の状態は変わった値だけ Write する。
- 書き込む型はノードの今の値の型に合わせる(最初に Read して覚える)。整数型のノードは I/O 表のスケールで換算し(例: Int16 の 1250 × 0.1 = 125.0)、Float / Double はそのままの値を使う。範囲外は型の端に丸める。
- 購読するノードの集まりが変わったら、サブスクリプションを作り直す。
- SecurityPolicy None・匿名ログインのみ。証明書の置き場所 (pki) は一時フォルダに作る。
- 通信は別スレッドの tokio ランタイムで行う。切れたら 1 秒ごとにつなぎ直す。
- 本物のサーバー相手のテストは `#[ignore]` にしてある(`PLANTWRIGHT_OPCUA_ENDPOINT` を指定して `cargo test -- --ignored opcua`)。必要なノードはテストのコメントにある。

## ログ再生

- `PlcLog::parse` は、出力の信号のログ列名(空なら信号名)を含む最初の行を見出しとみなす。区切りはカンマかタブ。
- 時刻列は見出しで探す(time / date / timestamp / 時刻 / 時間 / 日付 / 日時 など)。複数あれば空白でつないで読む。
  `2026/10/31 12:00:00.123`、`12:00:00.123`、秒の数値に対応。日付を先に引いてから秒にするので、ミリ秒の精度が落ちない。時刻だけの列で 12 時間以上戻ったら日をまたいだとみなす。時刻列がないログはエラーにする。
- 値は ON / OFF / TRUE / FALSE か数値。ワードの数値は I/O 表のスケールを掛けて物理量にする。使うのは出力の信号だけで、合わない列は画面に件数を出す。
- 再生中は時刻 t 以前の最後の行の値を出力とする(サンプル & ホールド)。設備モデルは再生速度ぶんの dt で進む。
- シーク (`seek_log`) は設備モデルを初期状態に戻し、0 から目的の時刻まで 10 ms 刻みで動かし直す。シリンダの途中位置まで記録どおりに再現するため。
- 文字コードは UTF-8 を先に試し、だめなら Shift_JIS ([encoding_rs](https://crates.io/crates/encoding_rs)) で読む(UI 層)。
- 再生の操作はタイミングチャートの再生バーではなく「PLC連携」ウィンドウに置いている(チャートの時刻表とログの時刻は別物のため)。

## 部品スクリプト

「部品スクリプト」モードでは、模擬 PLC の代わりに部品に付けたスクリプトが出力を書く(`PlcSession::scan_with`)。設計は [scripting.md](scripting.md)。

## 通信方式を足すとき

`usecase::PlcLink`(`exchange` と `status`)を実装したアダプターを作り、UI で接続時に `PlcSession::connect` に渡す。割り付け表・設備モデル・画面はそのまま使える。
