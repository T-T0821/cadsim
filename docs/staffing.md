# 人員配置の設計

工程シミュレーションの「人員」タブ(作業者の名簿・できる工程・シフト・人数の比較)のしくみをまとめます。使い方は [README](../README.md#作業者を割り当てて何人で回るかを見る) を見てください。工程シミュレーションそのものは [flow.md](flow.md) にあります。

## 層の分け方

| ファイル | 層 | 内容 |
| --- | --- | --- |
| `cadsim_core` の `staffing/model.rs` | ドメイン | 名簿(`Staffing` / `Worker` / `Skill`)、シフトと休憩(`Shift` / `Break`)、工程に人が要るか(`Labor`)、検証、`with_headcount` |
| `cadsim_core` の `staffing/compare.rs` | ドメイン | 人数を 1〜N 人に変えて回し、並べる(`compare_headcount`) |
| `cadsim_core` の `flow/sim.rs` | ドメイン | 作業者の割り当て・歩行・シフトの切り替えと、作業者ごとの集計(`WorkerStats`) |
| `src/flow/record.rs` | アダプター | `.plantwright` に書く形(`labor`、`staffing`) |
| `src/flow/xlsx.rs` | アダプター | 「作業者別」シート |
| `src/flow/staff_ui.rs` | UI | 人員タブ |

名簿は `FlowModel::staffing` に、人が要るかは `Element::labor` に入れています。工程モデルと一緒に保存・比較されるので、名簿を変えると「結果は前の設定のもの」の注意も出ます。

## モデル

| 項目 | 内容 |
| --- | --- |
| `Labor::None` | 人は要らない(今までどおり) |
| `Labor::Full` | 加工しているあいだずっと 1 人付く。人の速さで加工時間を割る |
| `Labor::Load { seconds }` | 1 個ごとの最初の `seconds` 秒だけ 1 人付く。その部分だけ人の速さで割り、残りは機械が自動で加工する |
| `Worker::skills` | できる工程と速さ(1.0 が標準)。速さは 10〜1000% |
| `Worker::shift` | 勤務するシフト。なければ休みなし |
| `Worker::absent` | 欠勤。シミュレーションに入れない |
| `Shift` | 始業・終業(終業が早ければ日をまたぐ)と休憩。毎日繰り返す |
| `Staffing::start_clock` | シミュレーションの 0 秒の時刻(既定 8:00) |
| `Staffing::walk_seconds` | 別の工程へ移るときの歩行時間(同じ工程を続けるなら 0) |
| `Staffing::rule` | 割り当てのルール(`AssignRule`) |
| `Worker::primary` | 持ち場(できる工程のうちの1つ)。`AssignRule::Primary` で使う |

時刻はすべて 0:00 からの秒で持ちます。

## 割り当てのしかた

工程シミュレーションの事象に、作業者の事象を3つ足しています。

| 事象 | すること |
| --- | --- |
| `WorkerShift` | シフト・休憩の切り替え。手が空いていればすぐ休みに入り、作業中・歩行中なら今の作業を終えてから抜ける。休みが明けたら人待ちの工程を探す |
| `WorkerArrive` | 歩いて工程に着いた。加工を始める |
| `OperatorRelease` | `Load` の人の作業が終わった。機械は加工を続け、作業者は次へ行く |

1. 人が要る工程にワークが入ると、加工時間を決めて「人待ち」(`State::NoOperator`)になり、作業者を呼びます。
2. 呼ぶのは、手が空いていて(`Idle`)その工程ができる作業者のうち、ルールでいちばん先に来る人です。

    | ルール | いちばん先に来る人 |
    | --- | --- |
    | `Fastest`(速い人が行く) | その工程の速さがいちばん速い人 |
    | `LongestIdle`(手待ちの長い人が行く) | 手待ちに入った時刻がいちばん早い人。仕事が均等に回る |
    | `Primary`(持ち場の人が先) | 持ち場がその工程の人。いなければ速い人 |

    同じなら、速い人 → 今その工程にいる人 → 名簿の上の人の順です。
3. 作業者は手が空くと、自分ができる人待ちの工程のうち、いちばん長く待っているところへ行きます。`Primary` のときは、自分の持ち場が人待ちならそこを先にします。
4. 別の工程なら `walk_seconds` 歩いてから始めます。
5. `Full` は加工が終わったとき、`Load` は人の作業が終わったときに手が空きます。故障したときは `Full` なら作業者がそのまま付いています(修理を待つ)。

作業者の状態は 作業・歩行・手待ち・休み の4つで、立ち上がりを除いた時間を状態ごとに数えます。稼働率は「出勤している時間のうち作業と歩行の割合」です。

品種が変わって段取り替えが要るとき([flow.md](flow.md#品種と生産計画))、人が要る工程では段取り替えも人の作業として加工の前に足します(`Full` は段取り + 加工、`Load` は段取り + 手作業を人の速さで割る)。段取り替えの間、作業者は「作業」です。

工程をラインに分けているとき([flow.md](flow.md#工場複数のライン))、名簿は工場で1つです。持ち場の工程が入っているラインをその人の所属とみなし、ほかのラインで終えた作業を「応援」(`WorkerStats::support_tasks`)として数えます。歩行時間はラインをまたいでも同じ `walk_seconds` です。

## 人数の比較

`compare_headcount` は、欠勤でない作業者を名簿の上から 1 人、2 人、… と残した名簿(`Staffing::with_headcount`)で同じ種のまま回し、排出数・スループット・作業者の稼働率の平均・人が要る工程の人待ちの割合の平均・仕掛数・リードタイムを並べます。目標のスループットを渡すと、それを満たすいちばん少ない人数を返します。誰を残すかは名簿の並び(↑ ↓)で決まります。

## ルールの比較

`compare_rules` は、名簿と人数をそのままに `Staffing::rule` だけを3通りに変えて回し、人数の比較と同じ値に加えて、作業者の稼働率のいちばん低い人と高い人(偏りの目安)と、歩いた回数の合計を並べます。

サンプル(日勤 3 人、8 時間)では次のようになります。速い人ルールでは速い A さん・C さんに仕事が集まり、B さんがほとんど使われず、C さんが加工と検査を行き来します。

| ルール | 排出数 | 稼働率(低い人〜高い人) | 歩いた回数 |
| --- | --- | --- | --- |
| 速い人が行く | 629 個 | 3%〜71% | 1,188 回 |
| 手待ちの長い人が行く | 729 個 | 30%〜82% | 485 回 |
| 持ち場の人が先 | 757 個 | 25%〜92% | 3 回 |

- ラインをまたぐ歩行を、ライン内の歩行より長くする
